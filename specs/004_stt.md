# 004 STT

## Purpose

Specify speech-to-text boundaries for the MVP while avoiding mandatory heavyweight model dependencies.

## Requirements

- Define a speech-to-text backend interface.
- Provide a mock backend for deterministic tests and demos.
- Add a real optional `faster-whisper` backend that can transcribe a recorded WAV file.
- Add a placeholder backend for future `whisper.cpp` integration.
- Do not require Whisper dependencies to run tests or mock mode.
- Support `stt_backend`, `stt_model_size`, `stt_device`, `stt_compute_type`, and `stt_language` config options.

## Non-goals

- No model download automation.
- No streaming transcription.
- No speaker identification.

## Interfaces

- `SpeechToTextBackend.transcribe(frames: Sequence[AudioFrame]) -> Transcription`
- `SpeechToTextBackend.transcribe_wav(wav_path: Path) -> Transcription`
- `Transcription(text, confidence, backend)`
- `MockSTTBackend(transcript)`
- `FasterWhisperBackend(model_size, device, compute_type, language)`
- `WhisperCppBackend(whisper_cli_path, model_path)`

## Acceptance criteria

- Mock backend returns configured text.
- FasterWhisper backend raises clear `RuntimeError` messages for missing dependency or model load failures.
- WhisperCpp placeholder fails with a clear `NotImplementedError`.
- Router receives plain transcript text.

## Test cases

- Full mock pipeline uses `MockSTTBackend`.
- Selecting `faster-whisper` falls back cleanly when the optional package is unavailable.
- Empty transcript routes to safe fallback.

## Open questions

- Should the first real backend be `faster-whisper` or `whisper.cpp`?
- How should model paths be configured?
